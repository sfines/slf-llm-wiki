# Prompting Framework for DDD

The **Prompting Framework for DDD** is a five-step sequential process introduced by [Eisenreich et al. (2026)](../raw/automating-ddd-paper.md) to automate the transition from business requirements to technical architecture.

## Framework Stages
1.  **[Ubiquitous Language Generation](ddd-ubiquitous-language-automation.md):** Creating glossaries and terminologies from domain text.
2.  **[Event Storming Simulation](ddd-event-storming-simulation.md):** Identifying domain events and commands through model-driven brainstorming.
3.  **[Bounded Context Identification](ddd-bounded-context-identification.md):** Grouping events and defining the strategic boundaries.
4.  **[Automated Aggregate Design](ddd-aggregate-design.md):** Identifying entities and value objects within each context.
5.  **[Architectural Technical Mapping](ddd-technical-mapping.md):** Proposing API designs, database schemas, or code structures.

## Logic
The framework relies on the model's ability to maintain context across a long sequence of architectural decisions. Each step consumes the artifacts generated by the previous one.
